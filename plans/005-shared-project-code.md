## Goal
Client request 2026-09-29, item 1: one customer project can have several Work Orders, and they must be able to share the same **project code**. Use the existing `Project.code` field; do not add a new one.

On the New project form, the "Project code" field works like the Client field:
- **Pick** an existing code from a list,
- **Type** a new one, or
- **Leave it blank** to auto-generate `<client ref>-<next number>` as today (`nextClientProjectCode`).

Existing projects keep their codes.

**Today:**
- `Project.code` is `@unique` (`prisma/schema.prisma`, model `Project`; index `pm_projects_code_key` in `prisma/migrations/20260925000000_baseline/migration.sql`).
- Both create paths reject a code that is already in use:
  - `createAutomationProject` (`src/modules/project-management/services/automation-project.service.ts`: `prisma.project.findUnique({ where: { code } })` → "Project code … is already in use.")
  - `createProject` (`src/modules/project-management/services/project.service.ts`, same check).
- The wizard's code field (`automation-project-wizard.tsx`, state `code`) is a plain text input.

**Safe to share:**
- Task codes are built from the project code (`${project.code}-PH1`, `${project.code}-T001`) but are only unique **per project** (`@@unique([projectId, code])` on `Task`). Two projects with the same code cannot collide.
- `nextClientProjectCode` takes max+1 per client prefix, so it is unaffected.
- The delete confirmation (`deleteProject`, type-to-confirm the code) is bound to the project **id**, so a shared code cannot delete the wrong project.

## Affected code
